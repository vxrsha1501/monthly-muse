How to use this script

  • Text inside a coloured box is verbatim — say it as written or in your own words; the meaning must stay.
  • SPEAKER A and SPEAKER B mark who owns the slide.
  • Handoff lines (in yellow) are spoken by the named speaker to pass the floor — say them out loud so the audience knows who is talking next.
  • Timings are cumulative from the start. Keep to them; if you run long, trim the roadmap slide, never the demo.
  • Run the demo on the deployed site (https://monthly-muse-bay.vercel.app) or, if the network is unreliable, on http://localhost:3000 with demo@monthlymuse.app / monthlymuse-demo. The December 2026 candidate batch is already generated, so the demo starts one click from the review screen.
  • Two appendices (pipeline stage reference, algorithm reference) are backup material for questions — you will only need them if the audience pushes past slide 7.
What is different from last term's script: candidates are now written by a hosted language model (Groq, openai/gpt-oss-120b) through a provider chain, not by the template engine. The template engine still exists and is still used — but only as an explicit, visible fallback, and only when MM_ALLOW_TEMPLATE_FALLBACK=true. Every batch records which provider wrote it, so the review screen can label it. If a model call genuinely fails the request is marked failed and the previous batch is kept; nothing is silently substituted. Say this plainly if someone asks — it is one of the project's better design decisions.

The monthly loop

Product flow3:15

Slide 6 — The AI pipeline 4:30 – 6:00

Fourteen stages, one language-model call

Core system6:00
SPEAKER A
"Generation is fourteen numbered stages. It starts by validating the brief — month, topic, audience, platform, tones, length, banned words — then assembles context, including the occasion only if two gates pass. Then preprocessing: keyword extraction and text normalisation."
"Stage four builds a 384-dimensional intent vector from the brief. Stage five is retrieval: cosine similarity against your whole history matrix picks three style exemplars and six recent posts, so the model sees how you actually sound. Stage six picks three style arms — a tone and a structure per candidate — with Thompson sampling, two exploiting what you liked and one exploring."
"Stage seven builds the prompt, and stage eight makes one call for six candidates. One call, six candidates: that's deliberate — it's the cost-efficient way to have something to choose from, and it keeps all six candidates comparable because they share a prompt."
"Then the filter chain: hard constraints on length, banned words and emoji level, Jaccard deduplication of opening lines, and embeddings. Features, scores, MMR for stylistic diversity, Monte-Carlo confidence, and finally the explanation payload — which is what you actually see on screen."
Handoff — A: "Now the maths. B."

Slide 7 — The maths 6:00 – 7:30

Scoring: s = F · w, then MMR, then confidence

Mathematical core7:30
SPEAKER B
"Each candidate becomes a row of six features, each normalised to zero to one: relevance — cosine between the candidate and the intent vector; tone — probability from our softmax classifier; personalisation — dot product with your preference vector; novelty — one minus the maximum cosine against your history; length — a z-score against what you usually write; and history — a Beta estimate of how this style did before."
"The score is a dot product, s equals F times w, with default weights of point three, point two, point two, point one five, point one and point oh five. Those weights are not fixed: when you reject something for being too similar, the novelty weight steps up. The update is a constrained gradient step — learning rate point oh one, step size point oh oh five, bound eight — projected back onto the simplex so the six weights always sum to one and never go negative."
"The score alone would give you three near-identical posts. So we add MMR — maximal marginal relevance — at lambda zero point seven, which trades relevance against diversity, with a quota that prefers a style arm not yet represented. That's why candidate three is tagged 'exploring a new style'."
"Confidence comes from a Dirichlet Monte-Carlo simulation: two hundred draws from a Dirichlet distribution centred on your weights, giving the probability that each candidate is rank one. It's seeded at forty-two, so the same inputs always give the same answer — that determinism is what makes golden-value testing possible. For rates in analytics we use Wilson intervals, because a naive percentage lies when n is small."

Appendix A — Pipeline stage reference

The fourteen stages, exactly as implemented (app/ai/pipeline.py)

#StageWhat it does · key parameters
1ValidateNormalises the brief, collects warnings; refuses malformed input before spending a model call
2ContextSeason and occasion resolved by the caller through the relevance + date gates; keyword extraction from topic, occasion and fact
3PreprocessNormalise, tokenise, lemma, coverage keywords for the hard constraints
4Intent vector384-d embedding of the brief text (topic, audience, purpose, tones, CTA, keywords)
5Retrieval (RAG)Cosine over the history matrix H: three style exemplars + six most recent posts
6Style armsThompson sampling over tone × structure arms, Beta posteriors, 2 exploit + 1 explore
7PromptSystem + user prompt carrying brief, arms, exemplars, recent posts, voice notes, banned words
8GenerateOne provider call for six candidates; provider chain, breaker, retry; template only if opted in
9FilterHard constraints: length per platform, banned words, emoji level, CTA, keyword coverage, near-duplicate history
10Embed384-d L2-normalised candidate embeddings; similarity matrices E·Eᵀ for dedupe and MMR
11FeaturesSix-feature row F: relevance, tone, personalisation, novelty, length, history
12Scores = F·w with the user's current weight vector
13Rank (MMR)λ = 0.7 with style-arm quotas so the top three differ; trace records the order and the top-3-by-score it replaced
14Confidence + explain200-draw Dirichlet Monte-Carlo → P(rank 1) and band; plain-English reasons; PCA coordinates for the embedding map
Failure path: if the provider returns nothing usable and the deployment has not opted into templates, the request is marked FAILED with the reason stored on the request — the previous batch stays intact and the UI says so. No silent substitution anywhere in the pipeline.

Slide 14 — Q&A preparation

Anticipated questions, with the suggested answer and who should take it.

QuestionWhoSuggested answer
Which model writes the candidates?B"Groq serving openai/gpt-oss-120b in production, behind an adapter that also supports Gemini, OpenAI, Anthropic and Ollama. Each provider has its own circuit breaker and model, so one provider's outage or quota doesn't take the system down."
What if the model is down or out of quota?B"The request fails visibly: status FAILED, the reason stored, the previous batch untouched. The offline template engine is still there as a last resort, but only when the deployment opts in with MM_ALLOW_TEMPLATE_FALLBACK=true — and when it is used, the review screen labels the batch as template-generated with an amber banner. We removed the silent substitution that used to hide failures."
Why not just use ChatGPT?B"A single model call gives you one answer with no ranking and no memory. We over-generate six from one call, then filter, embed, score and diversify with our own engine — and every user action feeds back into next month's ranking. The model is one component, not the product."
How is this different from a prompt?B"A prompt has no state. Ours has a preference vector, Beta statistics per style arm, learned length stats and a weight vector that updates with a constrained gradient step — all visible in Settings."
Is it really automatic?A"Yes — APScheduler runs a daily scan, creates the cycle for the upcoming month, gathers occasion context, generates, and notifies at T-3 and T-1 days. Preparation is idempotent, so a restart or a duplicate cron tick can't create two batches."
What does 'transparent' actually mean on screen?A"Three things: the provider and model that wrote the batch, the six-feature score breakdown per candidate, and plain-English reasons with a link to the nearest past post it was compared against. Plus provenance on the request itself — model, source, timestamp, fallback reason."
Why SQLite and not PostgreSQL?A"SQLite is the zero-setup default for development and for the free hosting tier. The schema is portable — string enums, UTC-normalised timestamps, vectors as float32 blobs — so pointing MM_DATABASE_URL at managed Postgres is the only change. That's the next deployment step."
Isn't 22% selection rate low?B"n is nine, so the Wilson interval is six to fifty-five percent — too early to read as a quality signal. It's also counting 'left unselected' events. The metric exists precisely so we don't over-claim from small numbers."
How do you stop it repeating itself?B"Three ways: n-gram Jaccard deduplication at generation, cosine similarity against your full history with a novelty feature in the score, and MMR with style-arm quotas so the three shown are stylistically distinct. There's also a repetition alert in analytics at cosine 0.85."
Why does a calendar occasion sometimes not appear?A"By design. An occasion existing in the calendar is not a reason to mention it. Two gates decide: semantic relevance between your objective and the occasion name — plus a narrow festive-intent bridge — and date eligibility. An unrelated post never gets a holiday bolted on."
What about privacy / API keys in the browser?A"The frontend only calls the public API and holds no secrets. Refresh tokens are httpOnly cookies; passwords are Argon2id. Provider keys live in platform environment variables, never in the repository or the browser."
How do you know what's deployed?A"The health endpoint reports the git commit it is running, taken from Render's environment, alongside provider, model, embedder and database status. That turned deployment verification from guesswork into one request."
What's the hardest part you'd redo?Either"Getting the golden tests written first. Several real bugs — candidates never being embedded, a naive/aware datetime mix, MMR returning two candidates from the same style arm, a silently substituted template batch — were caught before they could mislead anyone."
Can it handle multiple users?A"Yes — every query is scoped to the authenticated user, there's per-user rate limiting, and the API is stateless so instances can be added behind a load balancer. The scheduler worker is separate and shares only the database."
